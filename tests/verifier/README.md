# Independent verifier qualification

`machine.json` is a synthetic 300 mm Cartesian/shared-nozzle test machine, not a
printer profile or calibrated fingerprint. Its permissive speed/drive-flow and
loading limits support the small M1 regression corpus, including MMU loading and
unretraction. Startup position `(10,10,0)`, cold heaters and other dialect defaults
are explicit trusted assumptions; the M1 files do not home the machine.

Each `*.manifest.json` binds the exact decompressed accepted production G-code
under `tests/predictive/production/` and the exact machine file. Keep JSON LF
endings: hashes bind bytes, including whitespace. These fixtures do not alter the
M1 jobs or accepted output. Regenerating manifests is an explicit action:

```powershell
python tools/verifier_fixture_manifests.py
```

The ordinary test command never updates fixtures. It decompresses accepted
G-code into temporary files, runs the independent native executable and checks
that it has neither changed inputs nor created files. JSON reports are read from
stdout. All reports pass `verifier-report.schema.json`.

```powershell
python tools/trusted_verifier_tests.py build/trusted-verifier/jslice_verify.exe --evidence build/trusted-verifier/verification-evidence.json --production-replay build/m1_5-final-baseline
```

The optional replay directory is generated by the normal M1 four-mode production
runner. With it supplied, twenty-one unittest groups pass with no skips. Without it,
the actual off/on replay group is explicitly skipped. The twenty focused
production mutations rebind program hashes except when testing integrity itself;
each must reject for its exact intended error code and scan the entire input.
No production mutation passes through a hash mismatch or an unrelated error.
A two-fault test proves that an invalid tool after an unsupported command still
receives its own correctly located finding; scanning counters alone are insufficient.

Additional cases cover syntax, schema compatibility, hotend waits, fans, tools,
G92 physical offsets and retained retraction, absolute/relative E, speed/flow
overrides, heater shutdown, duplicate object IDs, unknown commands and required
unproven properties. A seeded decimal reference parser independently checks
hundreds of unit/mode/reset/motion commands. This is deterministic adversarial
testing, not a completed coverage-guided fuzz campaign.

The same tool correctly rejects the multi-material golden under the original
220 mm bed dimensions (first out-of-bounds move at line 204), while the other six
pass that check. Acceptance on the larger synthetic machine does not certify the
original 220 mm profile. The archived M1 file remains unchanged.

`evidence/` stores the starting/final M1 evidence, final native verifier evidence,
test logs, link contract and Windows DLL dependency inspection. Exact commands,
trust assumptions, mutation matrix and remaining M1.5 work are documented in
`docs/predictive-slicer/M1_5_STATUS.md` and `TRUSTED_VERIFIER.md`.
