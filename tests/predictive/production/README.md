# Accepted native Windows production outputs

These are actual Release CLI exports from the production slicing path, not
synthetic entity snapshots. Each `NAME.gcode.gz` is the first analysis-disabled
export; `NAME.artifact.json.gz` is the analysis-enabled report. Gzip uses mtime 0.
`evidence.json` records the first passing four-run qualification for every job.
`replay.json` records another four-run qualification against these accepted files.
Both use one DLL for ordinary and analysis modes; a separate historical binary
comparison is not implied. Exact launcher, engine DLL, comparator and input hashes,
commands, raw-byte comparisons, timestamp comments and coverage are included.

All 56 exports succeeded, all 28 reports passed the schema, and every comparison
passed. All non-timestamp G-code bytes and all repeated/accepted JSON bytes match.
Only `; generated by preFlight 1.2.0 on ` is ignored during canonical comparison.

Run the command in [the regression README](../README.md) with `--accepted` to
check both G-code and report goldens. It never updates this directory. Updating
accepted files requires reviewing production diffs, validating all four modes,
then explicitly copying/compressing reviewed outputs and recording their evidence.
A changed baseline must not be accepted just to hide a comparator failure.

The profile inputs are small synthetic regression cases, not calibrated printer
profiles. Source capture omits downstream emitter state and auxiliary expansion.
Read [M1_STATUS.md](../../../docs/predictive-slicer/M1_STATUS.md) for exact build
commands, known unqualified branches and the two discovered upstream defects.
